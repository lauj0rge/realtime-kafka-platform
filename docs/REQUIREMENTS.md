# ⚙️ Data Platform Technical Test ⚙️

## 🧑‍💻 Task description

Your team wants to explore real-time processing of domain events generated by our backend. 
For this POC, you will build a simple system where a random event producer generates simulated backend events, 
and a consumer will ingest these events into a PostgreSQL database.

The domain events will have the following format:
```json
{
  "event_type": "user_signup",
  "user_id": 12345,
  "timestamp": "2023-10-01T12:00:00Z"
}
```

The consumer needs to process these events and store them in a PostgreSQL database 🐘. For example, the previous event would be stored as:

| event_type  | user_id | timestamp            | consumed_at_ts |
|-------------|---------|----------------------|----------------|
| user_signup | 12345   | 2023-10-01T12:00:00Z | 1696161600     |


>[!NOTE]
> The `consumed_at_ts` is the timestamp when the event was consumed from Kafka.


We want to deploy two consumers:
- **Batch**. The consumer will run every _5 minutes_.
- **Real-time**. The consumer will process events as they arrive in the Kafka topic.

Each consumer will have its own table in PostgreSQL.

## ✅ Acceptance Criteria:
- The project must run in Minikube 🐳.
- The components must be deployed using Terraform 🛠️.
- The producer must send events to the Kafka topic endlessly, waiting 1 second between them 📤.
- Each consumer must consume these events and store them in an independent PostgreSQL table 💾.
- The project must include a README file 📖 with the instructions to run it 🛠️.
- Executing code from the host machine is not allowed. All services must run inside the Minikube cluster.
